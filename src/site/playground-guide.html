Playground guide

The playground runs the real Guchho bundler compiled to WebAssembly, entirely in your browser. Nothing you type is uploaded — the engine reads your source from an in-memory filesystem, builds or transforms it, and hands the result back.

How it works

The engine is @guchho/wasm, the same compiler that powers the native CLI, compiled to WebAssembly. The playground loads it inside a Web Worker so the interface stays responsive. A Build writes the file into the engine's virtual filesystem and runs the build command; a Print feeds the source to the engine's transform command over stdin and shows what it prints back.

Choosing a language

Use the Language selector to pick HTML, CSS, JavaScript, TypeScript, JSX, TSX or JSON. Changing it loads a starter example for that language; edit it freely. Reset restores the current language's example.

Build vs Print

Build
Runs the full build command with the selected options and lists every emitted file. HTML entries compile their inline scripts and styles.
Print
Runs a single-file transform — the engine's parser and printer — and shows the transformed code. Useful for seeing TypeScript stripped, JSX compiled, or CSS minified.

Options

The Options panel exposes settings the browser engine actually supports: target, format, platform, loader, minify and bundle. Settings that do not apply to the selected language are disabled. A build only runs when you press Build or Ctrl+Enter.

Output and errors

The right panel has four tabs. Output shows the generated file(s), Errors shows the engine's diagnostics, and Lexer and AST explain why token-level and tree-level views are not offered in the browser. Copy copies the visible output to your clipboard.

Not available in the browser

  • Print for HTML. The engine's transform command rejects the HTML loader, so the Print button is disabled for HTML — use Build instead.
  • Lexer and AST. The WebAssembly build exposes only the build entry point; token and syntax-tree access live in the native compiler API (lexer(), parse(), print()).
  • Source maps for builds. The --sourcemap flag crashes the browser engine, so it is shown disabled. The native CLI and API support it.
  • Serve, watch and dev. The engine has no sockets or threads; those subcommands are native only.
